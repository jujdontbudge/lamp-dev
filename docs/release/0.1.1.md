# Lamp 0.1.1

Lamp's first public release.

0.1.1 replaces 0.1.0, which was published on GitHub on 2026-11-12. GitHub
suspended that account the same day, so its repository and downloads are gone.
0.1.1 is the same software with two changes: Firecracker snapshot restore now
works on Linux arm64 (0.1.0 could not run any sandbox there), and the Go module
path, downloads and installer moved to `lamp.eilmer.si`, with the source on
[GitLab](https://gitlab.com/johansardar/lamp). Lamp is open-source software you install on your
own machines to run coding agents, harnesses and CI jobs in fast, isolated
sandboxes: Firecracker microVMs on Linux and Virtualization.framework VMs on
Apple Silicon Macs.

## What ships

| File | What it is | Licence |
| --- | --- | --- |
| `lamp-0.1.1-linux-amd64.tar.gz` | Signed installer release: `lampd`, `lamp`, `lamp-installer`, access, broker, network, MCP and CI executables, plus the prebuilt Linux engine (`lamp-supervisor`, `lamp-guard`) and its installer | Apache-2.0 |
| `lamp-0.1.1-linux-arm64.tar.gz` | The same for Linux arm64 (aarch64), with its own prebuilt Linux engine | Apache-2.0 |
| `lamp-0.1.1-darwin-arm64.tar.gz` | Signed installer release for macOS 26+ on Apple Silicon, with the VZ engine (`lamp-vz`, `lamp-supervisor`). Mac binaries are signed with a Developer ID certificate and notarized by Apple | Apache-2.0 |
| `lamp-relay-0.1.1-linux-{amd64,arm64}.tar.gz` | The optional self-hosted relay, shipped separately | AGPL-3.0-only |
| `eilmer-lamp-sdk-0.1.1.tgz` | TypeScript client (npm tarball) generated from the public schema, one method per API operation (330). Not on npm | Apache-2.0 |
| `install.sh` | The `curl \| sh` installer, with the archive digests and release key built in | Apache-2.0 |
| `release-trust.pub`, `SHA256SUMS` | The release signing public key and file checksums | — |

Each installer release holds a manifest signed with the release key (Ed25519).
`lamp-installer install` checks the signature, the platform and every file's
digest before it installs, and it pins the key for later updates. Each manifest
lists the exact Go module graph of each binary, and the licences travel inside
every release.

## Install

```sh
curl -fsSL https://lamp.eilmer.si/install.sh | sh
```

The installer downloads the archive for your platform from
`https://lamp.eilmer.si/releases/v0.1.1/` and
checks its SHA-256 against the digest built into the script. Then
`lamp-installer` checks the Ed25519 release signature against the release key,
also built into the script, and pins that key for later updates. It installs to
`~/.local/lamp` by default (`LAMP_PREFIX`). It uses systemd on Linux and
launchd on macOS (`LAMP_SERVICE=process` runs without a service manager).

The 0.1.1 installer starts a control-only daemon. It does not include a
seed/default template, enroll an engine or provide a working Mac engine setup.
It cannot take a fresh host to a sandbox on its own. The old Linux engine
helper modifies system paths; do not run it beside an existing installation.
See [the next release installation path](../install.md) for the replacement.

## Installed surface and optional components

The default 0.1.1 install serves the control API over a private Unix socket and
ships the CLI and MCP adapters. Sandbox execution requires separate privileged
engine enrollment and a prepared template. Other binaries and schema methods
include sessions, broker, networking, fleet and CI code, but they are not
configured by this install; some operations answer "operation not installed".
Do not infer installed features from the generated API catalogue. Automatic
gVisor fallback, model sign-in, native sessions, dashboard access, remote relay
access and fresh-VM CI enrollment are not provided by this installer.

0.1.1 is superseded by the prepared [0.1.2 release](0.1.2.md).

## Measured speed

Create met the owner's target. Live fork and native speed did not. Full,
honest numbers and their limits are in [release measurements](measurements.md).
They were measured once, on 0.1.0; 0.1.1 changes no x86_64 or macOS engine code.

## Dropped by the owner, 2026-11-12

- **Hosted eilmer.si sign-ups are not live.** The relay ships for you to run
  yourself; Eilmer's own hosted account stays invite-only. No owner machine can
  be reached from the Internet, and putting Cloudflare's edge in front would
  decrypt traffic there, which breaks RLY-002 (TLS between caller and host must
  not end at a third party).
- **No npm package.** The TypeScript SDK ships as a tarball in this release.
- **No Python SDK.** Only the TypeScript SDK ships; there is no Python SDK and no
  PyPI package.

## Not demonstrated

These features are built, but their real-account demonstration was dropped by
the owner and never run. Treat them as untested against the real service:

- Codex subscription sign-in (sessions and consoles).
- 1Password and Proton Pass kits.
- Gemini, Amp and GitHub Copilot subscription harnesses.
- GitHub Copilot cloud agent, and a stranger's fork pull request reaching a
  public-repository CI job.
- Hosted Buildkite, CircleCI, Azure Pipelines and Bitbucket Pipelines.

Also not demonstrated:

- Broker routes for OpenRouter, Stripe and AWS. A real `aws sts
  get-caller-identity` through the broker returned `UPSTREAM_UNAVAILABLE`.
- Moving active work to a Mac after losing a Linux fleet host.
- Replicated storage: it needs three storage hosts, and no measurement had them.

## Known limitations

- The public repository accepts no pushes or merges, admins included: every
  branch is protected with no one allowed to push or merge, so no private
  development branch can land there by mistake. The owner has to relax that
  before anything can be merged into the public repository.
- `.github/workflows` and `infra/ci` are the retired development CI for the old
  GitHub repository. They do not run on GitLab, and no runner serves the public
  project.

- Windows hosts and guests are not supported.
- Firecracker drives use the `Unsafe` cache mode, so guest flushes are not
  durable on the host disk.
- Automatic certificate renewal for hosted fleets is not scheduled; renewals
  are run by hand.
- Development evidence under `docs/development/` keeps failed runs as failed.
  Machine names, home directories and private addresses in it were replaced with
  placeholders before publication, including inside compressed observation files
  and profiles. The hash chains in the redacted T6 observation files no longer
  verify; the unredacted originals stay in the private development repository.
