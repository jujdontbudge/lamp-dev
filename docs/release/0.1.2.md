# Lamp 0.1.2 — developer preview

0.1.2 collects T32–T46: installation now includes a VM engine and a default
Linux template; CLI, MCP, HTTP and the local dashboard expose the installed
control surface. Optional agent, fleet, CI and credential integrations still
need explicit enrollment. This is software for your own machines, not a hosted
sandbox service.

## Install, execute, delete

Linux amd64/arm64 needs KVM and noninteractive administrator access. Apple
Silicon needs macOS 26+, APFS and a logged-in session, plus noninteractive
administrator access for isolated workers. Hosts without KVM do not fall back
to gVisor. Read [engine setup and requirements](../install.md#engine-setup),
especially disk space and the smaller memory default on an 8 GB Mac.

```sh
curl -fsSL https://lamp.eilmer.si/install.sh | sh
"$HOME/.local/lamp/current/bin/lamp" sandbox run -- python3 -c 'print("hello from Lamp")'
```

`run` creates a VM, waits, executes, returns the real exit code and deletes the
VM. Persistent create/exec/delete, PATH, credentials, a second prefix,
[update, rollback and uninstall](../install.md#update-rollback-and-remove-an-install)
are documented in the installation guide. Do not use the old 0.1.1 standalone
engine helper beside an existing installation.

## What the release contains

| Asset | Contents |
| --- | --- |
| `lamp-0.1.2-linux-amd64.tar.gz` | Signed control/CLI/MCP binaries, Linux supervisor/guard, Firecracker/jailer, engine installer and compressed Linux seed |
| `lamp-0.1.2-linux-arm64.tar.gz` | Same, built for Linux arm64 with its own Firecracker seed |
| `lamp-0.1.2-darwin-arm64.tar.gz` | Apple Silicon binaries, VZ supervisor/engine, engine installer and Linux seed; public Mac binaries must be Developer ID signed and Apple notarized |
| `lamp-relay-0.1.2-{linux-amd64,linux-arm64,darwin-arm64}.tar.gz` | Optional relay server, separate AGPL-3.0-only distribution |
| `install.sh`, `release-trust.pub`, `SHA256SUMS`, `release.json` | Digest-pinned installer, Ed25519 public key, checksums and exact build provenance |

The installer verifies the archive digest and signed manifest/payload, then
pins the release key for updates. Seeds are signed and verified too. Host/CLI
code is Apache-2.0; dependency licences travel with the archives. No SDK package
is released with 0.1.2. The owner deferred SDK work; the source tree's generated
TypeScript client retains its earlier package version and is not a supported
0.1.2 interface. Use CLI, MCP or HTTP.

## Available workflows and their limits

| Workflow / command | What is usable and what needs setup |
| --- | --- |
| `lamp template list`, `lamp sandbox create`, `lamp sandbox exec ID -- uname -a` | Engine/default Linux template enrolled at install; separate stdout/stderr, stdin and file transfer are available. Linux amd64, Mac M5/M2 Air and nested Linux arm64 candidate VM execution was demonstrated. These were fresh prefixes on existing OS installations. |
| `lamp quota`, `lamp sandbox list` | Live capacity accounting and deletable failed states. A supervisor restart loses volatile guests, marks them failed and reclaims reservations; it does not preserve the same live VM. Durable operation history still consumes control-record quota. |
| `lamp snapshot list`, `lamp backup list`, `lamp budget list` | Sleep/resume, memory snapshots, maximum age and task budgets. Encrypted sandbox/volume recovery needs state-admin enrollment and an offline recovery key configured before backup. Fresh-prefix recovery was shown on the same enrolled Ubuntu engine, not replacement-engine custody migration. See [lifecycle and recovery](../lifecycle-and-recovery.md). |
| `lamp template build`, `lamp template save-tools`, `lamp volume list` | [Template builds, saved tools, volumes and caches](../templates-and-storage.md). Mac offline wheel reuse and shared Linux-guest volume persistence were shown; online Mac template-build networking is unobserved. Native macOS guests do not implement Linux 9P mounts. |
| `lamp port expose`, `lamp network-policy list` | Guarded networking, loopback preview origins, private shares, WebSocket/SSE and live transport policies; [networking guide](../networking.md). Public access disables preview authentication, not loopback binding. Host/LAN denies remain. Strict TLS-site filtering and automatic preview wake are unavailable. |
| `lamp harness list`, `lamp session list` | Managed OpenCode; Codex requires explicit [host sign-in import and enrollment](../agents.md). Host custody keeps those upstream credentials outside the guest. Claude subscription custody is unsupported. Eleven catalogue entries are not eleven ready agents. |
| `lamp session spawn`, `lamp sandbox diff`, `lamp sandbox pull-changes` | [Agent workflow](../agent-workflow.md): branch-isolated children, returned committed changes, side chats and enrolled host/VM moves. Codex host/VM conversation continuation and T3 Code/Herdr bridges were shown with private enrollment. Ignored files and running processes do not move. Active sides block moves; continuation quota is 16 MiB. No four-VM concurrency or timing parity is claimed. |
| `lamp kit list`, `lamp sandbox kit ID --kit python` | [Kits](../guides/kits.md) download guest packages on first use. Python, Chromium, guest Docker, TypeScript LSP and virtual desktop passed on Ubuntu amd64 and the M5 VZ Linux guest. **Docker, LSP and desktop are unverified on Linux arm64 hosts.** Air five-kit coverage is unobserved. |
| `lamp dashboard`, `lamp sandbox metrics ID`, `lamp sandbox logs ID` | Installed loopback [dashboard](../dashboard.md), private one-use sign-in, retained metrics and bounded logs. Templates need a current guest helper. Missing counters are unavailable, not zero. |
| `lamp plugin list`, `lamp job list` | [CI and control enrollment](../control-operations.md) is required. A disposable native Forgejo public/untrusted job ran in a fresh Ubuntu VM, saved a log and removed runner/VM authority. Ten adapter descriptors are not ten verified native services. No current real GitLab job or stranger-fork job is claimed. Public/PR jobs must use fresh VMs without owner secrets. |
| `lamp host list`, `lamp update list`, `lamp relay list` | [New-fleet provisioning and remote access](fleets-and-access.md) require private enrollment. Cross-machine routing and clean template placement were shown; rolling control updates/rollback and encrypted SSH relay were shown separately. Initial membership is immutable. Production account/TLS enrollment and a disposable Tailscale tailnet were not demonstrated. Unavailable private disks stay on their home host; no automatic state promotion. |
| `lamp secret list`, `lamp connection list` | Explicit [model, settings and service enrollment](../agents.md). Opaque secret markers work through `lamp secret use` for exact approved HTTPS hosts, not arbitrary curl rewriting. Credential echo observations are bounded and are not a complete zero-leak measurement. |
| `lamp --help --json`, `lamp version --json` | Connected CLI discovery, MCP tools and served OpenAPI describe installed handlers. An installed handler can still require enrollment/capacity. Client, daemon, supervisor, installer and MCP use the release version; OpenAPI keeps the contract version separately. The source schema is the full vocabulary, not an installed-feature promise. |

## Not in this release / not established

- Windows hosts/guests, automatic gVisor fallback, Claude subscription custody,
  hosted self-service accounts, npm/Python SDK releases and automatic migration
  of lost-host private VM state.
- Linux Firecracker display, audio, keyboard, mouse or GPU passthrough. The
  desktop kit is a guest virtual X display. The included Mac seed runs Linux;
  it is not a redistributable macOS guest image.
- Online fleet membership changes or in-place conversion of standalone state
  into a fleet. Certificate renewal for generated fleet certificates is manual.
- Complete replicated-storage demonstration (requires a storage quorum),
  all catalogue agents/CI systems, or release-wide secret-leak certification.
- A complete cold-to-five-kit run on Linux arm64. Prior failures remain failures;
  Mac aarch64 results do not substitute for Linux arm64 host observations.

Firecracker drive cache mode is `Unsafe`: guest flushes can stop in host cache.
Do not interpret the old disk-throughput ratios as durable native-speed parity.
Mac memory fork/resume requires an unlocked login session. Backups buffer
compressed/encrypted objects in host memory and omit templates, engine custody
lineage, host credentials, signing keys and live volume attachments.

## Measurements

[Release measurements](measurements.md) names the platform, version and scope of
each observation. The Ubuntu amd64 T32 signed candidate took **165.473 s** from
install through code and cleanup over local HTTP, missing the two-minute goal.
Older 0.1.0 Ubuntu create met its p50 target; live fork and native speed missed
parts of their targets. Those are historical measurements, not 0.1.2 results.
Fresh 0.1.2 create, live-fork, native-speed and zero-leak observations will be
reported once at release, with missing observations and failures stated. They
do not gate implementation or release.
