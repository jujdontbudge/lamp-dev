### Section 19: standard and allocations

- Standard is **2 vCPU/4 GiB/20 GiB**, with **0/128 MiB/1 GiB** recently written RAM cases. Full 4 GiB capture remains required. Hard targets apply only on native Linux standard rows: create p50 <500 ms, every fork <1000 ms and each native-speed point ratio ≥0.97. Mac/Windows have measurements pending targets; LA is nested, not native speed evidence.
- Fork phase allocations changed to **20,35,75,70,500,100,35,65 ms**, total **900 ms**. Create allocations remain 20,35,50,60,150,45,0,90 ms, total 450 ms; headroom remains 50/100 ms. Standard capture at 500 ms requires **≥8 GiB/s** before other work; 8 GiB capture would need **≥16 GiB/s** in that phase. Local and replicated barriers/receipts remain in the bound.
- 128 MiB and 1/2/8 GiB RAM, full-dirty 4 GiB, larger and extra device/durability rows are published measurements with universal correctness gates. Retain 20 warmups, 200 creates/case, 100 forks/row and ≥10 randomized paired native measures. The 95% lower-bound ≥0.97 objective is explicitly proposed, not an undeclared release gate.
- `lamp.benchmark/v1` stays the protocol. Missing/failed fixed owned-matrix results block merge; pending community native-arm64 speed certification does not block the owned-machine matrix.
